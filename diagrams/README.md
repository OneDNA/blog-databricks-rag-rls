# Diagrams

Three editable draw.io sources. GitHub renders `.drawio` files natively — click one and it opens in
a viewer, no export needed.

| File | What it shows |
| --- | --- |
| [`build-and-serve.drawio`](build-and-serve.drawio) | The two halves of the platform: what build writes and what serve reads. Start here. |
| [`architecture.drawio`](architecture.drawio) | The whole system on one page: identity, build, serve. |
| [`decision-tree.drawio`](decision-tree.drawio) | Which enforcement path to use, and the host constraint that follows. |

## Two colour rules, and they never disagree

All three follow the Databricks brand system, which has one rule at its centre:

> **Lava `#FF5F46` marks Databricks. Oat `#D9D7CE` marks everything that is not.**

On top of that, they use **border colour to say who enforces access control** — which is the
argument the article makes, rendered as a visual convention:

| Border | Meaning |
| --- | --- |
| **Green** `#71C5AD` | **Unity Catalog enforces.** Per caller, platform-side, gives notice when it goes wrong. |
| **Lava** `#FF5F46` | **Your code enforces.** Only as good as you wrote it. |
| **Deep lava** `#FF3621` | **Nothing enforces.** The security plane does not reach here. |
| **Oat** `#D9D7CE` | Outside Databricks entirely. |

Read the architecture diagram by border colour before you read it by arrow. Every silent failure
described in the article sits on a lava or deep-lava border — that is not decoration, it is the
whole point.

## Icons

Every icon is official vendor artwork, embedded in the file as a base64 data URI. No external
fetch, no shape library to install, nothing to break when a CDN moves. Draw.io's own built-in
stencils are not used anywhere: they approximate a vendor's mark rather than reproduce it.

| Source | Used for |
| --- | --- |
| Databricks architecture icons | AI Search, Unity Catalog, ABAC, Genie, Model Serving, Databricks Apps, SQL Warehouse, Lakebase, Agent Bricks |
| Microsoft 365 content icons (Teams Purple) | Teams, the person mark |
| Azure Public Service Icons V24 | App Registrations, for the token exchange |

Two notes on what is deliberately absent. There is no plain "Entra ID" mark in the Azure V24 set,
so the RFC 8693 exchange is drawn with **App Registrations** — which is more accurate anyway, since
an app registration is exactly what the federation policy trusts. And the Teams bot is drawn with
the Teams mark rather than a bot glyph, because the bot is not a separate product.

The Databricks artwork comes from the community-maintained
[databricks-architecture-icons](https://github.com/oieduardorabelo/databricks-architecture-icons)
collection, which repackages official SVGs without redrawing them. That set is **unofficial** —
Databricks neither sponsors nor endorses it. Databricks, the Databricks logo and the product names
are trademarks of Databricks, Inc. Microsoft, Teams, Azure and Entra are trademarks of Microsoft
Corporation. Check both vendors' brand guidelines before commercial use.

## Regenerating

All three are generated by [`build.py`](build.py) rather than hand-edited, for one reason: the
brand rule and the enforcement rule have to hold on **every** shape, and keeping that consistent by
hand across a hundred-odd cells is how a diagram drifts out of step with the argument it makes.

```bash
python build.py
```

Colour tokens live at the top of that file. Change one there and all three follow.

**The build fails on a layout error rather than shipping one.** Six checks run before a file is
written, because every one of these failures is invisible in the XML and obvious on the canvas.

*Text that does not fit its box.* draw.io never grows a shape to fit its label, so an undersized
box renders text across its own border:

```
LAYOUT: 'guard' needs ~62px of text height but the box is 60px (usable 44px).
```

Six boxes were caught this way on the first run.

*Lines that cross shapes.* Two separate causes. draw.io resolves edge waypoints against the edge's
**parent**, not the page, so an edge inside a swimlane given page coordinates has every waypoint
shifted by the lane offset. And an edge between two boxes that are not aligned is drawn as a
straight or dog-legged run that passes through whatever sits between them, with no waypoint
involved at all:

```
LAYOUT:
  edge q2 waypoint (840,640) sits inside guard
  edge cross is drawn across acln
  edge cross is drawn across agent
```

The first form caught nine misplaced waypoints. The second needed a segment test rather than a
point test — checking waypoints alone passes a line that crosses three shapes between them, which
is how a cross-lane connector shipped drawn over half a diagram.

*Shapes escaping their swimlane.* A child positioned above `startSize` is drawn **under the lane's
header bar**, and one positioned past the lane's width or height spills outside it. draw.io clips
neither:

```
LAYOUT:
  apps sits under the idlane header (y=20, header=44)
  cols overflows pipe to the right by 120px
```

*Siblings inside a lane overlapping, and top-level blocks overlapping.* Growing a lane or moving a
note pushes nothing else out of the way, so a shape silently ends up underneath its neighbour.

*Icon badges drifting off their box.* Badges are positioned relative to the box they label, and the
check confirms each one is still inside it and that the box's label starts clear of it.

Every check is verified against a deliberately broken build rather than assumed to work. That
matters more than it sounds: the first version of the crossing check sat in this file for three
rounds reporting "clean" because it was never actually being called, and the second version missed
diagonal lines entirely. A guard that has only ever passed is a guard you are hoping about.

Minimum font size is 10px, checked by eye rather than by the build.

## Typography

The brand font is **DM Sans**, and the brand system's `fontSource` points at Google Fonts. That
only helps in the web editor: **the draw.io desktop app and any local render use installed fonts
only**, so on a machine without DM Sans the diagram silently drops to a default and looks nothing
like the brand. Nothing warns you — the XML is correct either way.

So the files declare a chain rather than a single family:

```
fontFamily=DM Sans, DM Sans 14pt, Segoe UI, Helvetica Neue, Helvetica, Arial, sans-serif
```

`DM Sans` is the web and macOS name. **`DM Sans 14pt` is what the variable font registers itself as
on Windows** — asking only for `DM Sans` there misses, which is the kind of detail that costs an
afternoon. Segoe UI and Helvetica cover Windows and macOS if neither is present.

To get the true brand font locally, install it from
[Google Fonts](https://fonts.google.com/specimen/DM+Sans). On Windows a per-user install is enough:
drop the TTFs in `%LOCALAPPDATA%\Microsoft\Windows\Fonts` and register them under
`HKCU:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts`. No admin rights needed.

Hand-editing the `.drawio` files directly works for a one-off tweak, but the next `build.py` run
overwrites it — and skips the layout check on the way past.

## Editing

Open at [app.diagrams.net](https://app.diagrams.net) (File → Open from → Device), or in the VS Code
[Draw.io Integration](https://marketplace.visualstudio.com/items?itemName=hediet.vscode-drawio)
extension, which edits the XML in place.

## Exporting

If you need PNG or SVG — for slides, or a platform that will not render `.drawio` — the draw.io
desktop app exports from the command line:

```bash
drawio -x -f svg --scale 1.5 -o architecture.svg architecture.drawio
drawio -x -f png --scale 2   -o architecture.png architecture.drawio
```

Exports are deliberately **not** committed. A stale PNG beside an edited source is worse than no
PNG at all: it looks current, and nothing about it says otherwise. Which is, fittingly, the same
failure mode the article is about.
